📝 Завдання
Завдання 1: Послідовність викликів ⏱️🚦
Мета: Зрозуміти, як setTimeout ставить функцію в чергу, а не виконує одразу.
Завдання: Напишіть скрипт (script.js), який виводить у консоль: "Початок" (одразу), "Середина" (через 1 сек), "Кінець" (через 2 сек).
Очікуваний результат (в консолі): Початок -> (пауза ~1с) -> Середина -> (пауза ~1с) -> Кінець.
Самоперевірка: Повідомлення з'являються в правильному порядку з приблизними затримками.
💡 Цікавинка: Навіть setTimeout(..., 0) не виконається миттєво! Функція потрапить у чергу і виконається тільки тоді, коли основний потік JavaScript буде вільний (після поточного коду). Це називається "наступний тік" Event Loop.
Завдання 2: Обіцянка даних 🤝🎁
Мета: Створити та "виконати" Promise, імітуючи асинхронний запит.
Завдання:
HTML (index.html): div#data-container + кнопка "Завантажити".
JS (script.js):
Функція WorkspaceData повертає Promise, що через 3 секунди вирішується (resolve) рядком "Дані отримано!".
При кліку: кнопка блокується, в div пишемо "Завантаження...", викликаємо WorkspaceData.

Самоперевірка: Інтерфейс реагує як описано, дані з'являються після паузи.
💡 Цікавинка: Проміси можуть бути в трьох станах: pending (очікування), fulfilled (успішно виконано), rejected (помилка). Назва "Promise" вказує на те, що це об'єкт, який обіцяє повернути значення колись у майбутньому.
Завдання 3: Гонка за ресурсами 🚀🏁
Мета: Запустити кілька асинхронних операцій паралельно і дочекатися завершення всіх.
Завдання:
HTML (index.html): div#results + кнопка "Запустити все".
JS (script.js):
Три функції (WorkspaceResource1/2/3), кожна повертає Promise з різним часом вирішення (1с, 3с, 2с) та своїм текстом ("Ресурс 1/2/3 готовий").
При кліку: в div пишемо "Завантаження...", використовуємо Promise.all([...]) для запуску всіх трьох.
Коли Promise.all виконається, очищуємо div і виводимо всі три результати.
Очікуваний результат: Клік -> "Завантаження..." -> (~3 сек) -> Всі три повідомлення "Ресурс X готовий" з'являються одночасно.
Самоперевірка: Всі результати з'явилися разом після найдовшої затримки.
💡 Цікавинка: Promise.all дуже зручний, але має особливість: якщо хоча б один з переданих промісів завершиться з помилкою (reject), то весь Promise.all негайно завершиться з цією ж помилкою, не чекаючи на інші. Для випадків, коли треба дочекатися всіх (навіть помилкових), існує Promise.allSettled.

Завдання 5: Лічильник під контролем ⏲️💧🚫
Мета: Навчитися запускати та, що важливо, зупиняти періодичні дії (setInterval), щоб уникнути витоків пам'яті.
Завдання:
HTML (index.html): span#timer (початково 0), кнопки "Старт" (#start-btn) та "Стоп" (#stop-btn).
JS (script.js):
Змінна для ID інтервалу (intervalId = null).
"Старт": Якщо intervalId ще немає, запускає setInterval (раз на секунду збільшує число в #timer), зберігає ID в intervalId, блокує "Старт", активує "Стоп".
"Стоп": Викликає clearInterval(intervalId), обнуляє intervalId, блокує "Стоп", активує "Старт".
Очікуваний результат: Кнопка "Старт" запускає лічильник, "Стоп" — зупиняє. Неможливо запустити другий лічильник, поки перший працює.
Самоперевірка: Лічильник коректно запускається/зупиняється, немає "прискорення" при повторних кліках на "Старт".
💡 Цікавинка: Незавершені інтервали (setInterval) або необроблені слухачі подій (addEventListener) — часта причина витоків пам'яті в JavaScript. Браузерний збирач сміття не може видалити об'єкти, на які існують "живі" посилання (як-от активний таймер), навіть якщо ви вже не використовуєте елемент, до якого він прив'язаний. Тому завжди очищуйте таймери та видаляйте слухачі, коли вони більше не потрібні!
